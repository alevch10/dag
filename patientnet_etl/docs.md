# Airflow DAG для подготовки данных из МИС Patient.Net
## Обновление KPI по выручке
### Цель: 
Ежемесячный расчёт и актуализация суммы выручки по платным услугам. Используется для расчета KPI продуктовой команды.
### Процесс
#### Определение последнего обработанного месяца
Выполняется запрос GET_LAST_MONTH, который возвращает последний месяц, присутствующий в таблице kpi.revenue_kpi. Если таблица пуста – начальной датой считается 1 января 2025 года.

#### Формирование списка месяцев для пересчёта
Если данные отсутствуют – цикл начинается с 2025-01-01.

Если данные есть – пересчитываются два последних месяца (предыдущий месяц перед последним имеющимся и сам последний имеющийся), а затем все последующие месяцы вплоть до текущего месяца включительно.

Это необходимо, чтобы корректно учитывать платежи, поступающие с задержкой (услуги могут оплачиваться спустя некоторое время после оказания).

#### Расчёт выручки за месяц
Для каждого месяца выполняется сложный SQL-запрос SELECT_REVENUE_KPI, который:
1. Отбирает услуги по рецептам, созданным в заданном интервале (presc.upd_dt),
2. Исключает бюджетные типы оплаты (pay_type NOT IN ('sp_budget', 'budget')),
3. Учитывает только определённого создателя (системный пользователь с OID 5e95e526-...),
4. Применяет скидки (процентные и фиксированные) в зависимости от наличия финансового плана с фиксированной скидкой,
5. Округляет итоговую сумму согласно настройке DiscountAmountRounding из таблицы mir.systemsettings.
6. Возвращает агрегированную сумму (revenue) за месяц.

#### Сохранение результата
Полученная сумма вставляется или обновляется в таблице kpi.revenue_kpi с помощью запроса UPDATE_REVENUE_KPI (конфликт по полю month разрешается обновлением значения revenue).

### Схема таблицы kpi.revenue_kpi
``` md
| month      | revenue   |
|------------|-----------|
| 2025-01-01 | 123456.78 |
```
- month – дата, приведённая к первому числу месяца (тип DATE), первичный ключ.
- revenue – сумма выручки за месяц (тип NUMERIC).

### Используемые SQL-запросы
- GET_LAST_MONTH – выбор последнего месяца из таблицы kpi.revenue_kpi.
- SELECT_REVENUE_KPI – расчёт выручки за заданный период (параметры {start_month}, {end_month}).
- UPDATE_REVENUE_KPI – вставка/обновление записи в kpi.revenue_kpi.

## Обновление KPI по соотношению записей ОЗ Веб к КЦ
### Процесс
#### Получение последнего месяца для call-центра
Запрос SELECT_LAST_CALL_CENTER_DATE возвращает последний месяц, для которого уже есть агрегированное количество записей из call-центра в таблице kpi.rate_kpi.

#### Расчёт количества записей call-центра
Запрос GET_CALL_CENTER_APPOINTMENTS возвращает количество записей, созданных сотрудниками call-центра (определяются по должностям) за указанный месяц. Результат сохраняется в kpi.rate_kpi через UPDATE_CALL_CENTER_KPI с источником 'call_center'.

#### Получение последней даты для онлайн-записей
Запрос SELECT_LAST_OB_DATE возвращает последний месяц, для которого в таблицу kpi.appointments загружены детальные записи из онлайн-канала.

#### Загрузка детальных записей онлайн-канала
Запрос GET_OB_APPOINTMENTS выбирает записи (ID и дату создания) из МИС, созданные определённым пользователем (системный OID 5e95e526-...), за указанный месяц. Полученные данные вставляются в таблицу kpi.appointments с помощью load_appointments (используется INSERT ... ON CONFLICT DO NOTHING для исключения дубликатов).

### Схема таблиц 
#### kpi.rate_kpi
Таблица содержит количество записей, сделанных через разные каналы за календарный месяц
``` md
| month   | revenue | source      |
| --------|---------|-------------|
| 2025-01 | 100000  | call_center |
``` 
- create_dt – первый день месяца (тип DATE).
- source – источник ('call_center' или 'ONLINE_BOOKING').
- count – количество записей (тип INTEGER).

#### kpi.appointments
Таблица содержит записи из МИС, сделанные через сервисы онлайн-записи
``` md
| create_dt           | appointment_id                       | 
| ------------------- | ------------------------------------ |
| 2025-01-01 12:00:00 | 123e4567-e89b-12d3-a456-426614174000 |
``` 
- create_dt – дата и время создания записи.
- appointment_id – уникальный идентификатор записи (первичный ключ).

#### kpi.online_appointments
Таблица содержит записи из ESB с распределением по каналам записи.
``` md
| create_dt           | appointment_id                       | source         |
| ------------------- | ------------------------------------ | -------------- |
| 2025-01-01 12:00:00 | 123e4567-e89b-12d3-a456-426614174000 | ONLINE_BOOKING |
``` 
- create_dt – дата и время создания записи.
- appointment_id – уникальный идентификатор записи.
- source – канал записи (например, ONLINE_BOOKING).

### Дальшейшие действия для получения 
1) Выполнить запрос в БД ESB: ``` sql SELECT DISTINCT ON (appointment_oid) appointment_oid, source FROM sgm_schedule.appointment_record where date(created_at) > '2025-01-01' ORDER BY appointment_oid, updated_at DESC ```, он выгрузит продукт, через который сделаны записи. Данные необходимо загрузить в таблицу kpi.online_appointments
2) Выполнить запрос в БД DWH: ``` sql ```, он выполнит расчет количества записей, сделанных через Веб ОЗ и запишет их в таблицу kpi.rate_kpi 

## Структура DAG patientnet_etl
DAG запускается ежедневно в 1:00 UTC и выполняет три независимые цепочки задач последовательно (для упрощения управления):

### Revenue KPI
- get_last_month → определяет последний обработанный месяц.
- get_revenue → пересчитывает выручку за два последних месяца и все последующие до текущего, обновляет kpi.revenue_kpi.

### Call-центр KPI
- get_call_center_last_month → получает последний месяц для call-центра.
- process_call_center_amount → рассчитывает количество записей и обновляет kpi.rate_kpi.

### Онлайн-записи (загрузка деталей)
- get_ob_last_month → получает последний месяц загруженных онлайн-записей.
- process_ob_appointments → выгружает новые записи из МИС и загружает их в kpi.appointments.

Все задачи используют соединение dwh_pg (PostgresHook) для работы с базой данных DWH. В случае ошибки предусмотрено две повторные попытки с интервалом 30 минут.
